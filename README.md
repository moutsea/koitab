# 🐟 KoiTab — 浏览器标签页整理助手

一款支持 **Chrome** 和 **Edge** 的浏览器插件,帮你一键整理杂乱的标签页:

- **🖌 水墨书签风界面** — 宣纸底、界格线、朱砂印章、楷宋衬线字(全走系统字体,零下载)
- **🧭 三 tab 弹窗** — 诊断(体检报告 + 整理/归档预览)· 标签页(分组列表)· 收藏夹,停留的 tab 会记住
- **⚡ 一键整理** — 一个按钮依次完成:关闭重复 → 取消孤儿分组 → 分组收进当前窗口、散标签收进新窗口 → 收拾剩余标签 → 分组靠左重排
- **🪟 整理成两个窗口** — 当前窗口集中展示所有站点分组,不属于分组的散标签统一收进一个新窗口
- **🧹 自动取消孤儿分组** — 只剩 1 个标签的分组自动取消,不留无意义的分组位
- **📐 分组靠左重排** — 分组的标签页挨着排在最左,未分组的一律排到右边,不再交错
- **📁 按站点折叠** — 分组可折叠并记忆状态,标签页再多也能快速扫视各类别
- **🪟 跨窗口整理** — 可在「本窗口 / 所有窗口」之间切换,多窗口一起整理
- **🧩 合并同类项** — 把相同网站的标签页自动收进带颜色的浏览器原生标签分组
- **📚 归档未用标签** — 长期没用的页先收进 KoiTab 自己的收藏夹(本地存储,不碰浏览器书签)再关闭,随时能找回
- **🧹 关闭重复网页** — 自动检测并关闭内容完全相同的重复标签页(优先保留固定/正在浏览的页面)
- **🔍 快速搜索** — 按标题或网址搜索,点击即跳转
- **📊 标签页统计** — 实时显示标签页 / 站点 / 重复数量
- **🔒 隐私优先** — 全部逻辑本地运行,无任何数据上报

## 版本约定

版本号写在 `extension/manifest.json` 的 `version` 字段,并在 `CHANGELOG.md` 记录:

- **每次改动都升级版本号**:新增功能升次版本(`1.0.0 → 1.1.0`),问题修复升修订号(`1.1.0 → 1.1.1`)
- 弹窗右上角的 `v…` 徽标即当前版本,方便确认浏览器加载的是哪一版
- 改完记得在 `chrome://extensions` 点刷新 ↻,让浏览器重新读取 manifest

## 安装插件(开发者模式)

### Chrome

1. 打开 `chrome://extensions`
2. 打开右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**,选择本项目的 `extension/` 目录
4. 工具栏出现锦鲤图标即安装成功

### Edge

1. 打开 `edge://extensions`
2. 打开左侧 **开发人员模式**
3. 点击 **加载解压缩的扩展**,选择 `extension/` 目录

> 💡 建议点击工具栏拼图图标,把 KoiTab 固定到工具栏,随手整理。

## 官网(Next.js)

官网是独立的 Next.js 应用,在 `nextjs/`:App Router + **全静态预渲染(SSG)**,
SEO 元数据、JSON-LD、sitemap、RSS 全部在构建期生成。

```bash
cd nextjs
npm ci               # 首次
npm run dev          # 本地预览 http://localhost:3000
npm run build        # 生产构建(验证用)
```

> **构建期别带 `NODE_ENV=development`**:Next 的已知缺陷会让 `next build`
> 在预渲染 `/_global-error` 时崩在 `useContext of null`
> ([vercel/next.js#97046](https://github.com/vercel/next.js/issues/97046))。
> 正常 shell 不带;若工具链带了,用 `NODE_ENV=production npm run build`。
> `tools/build-site.py` 已强制 production。

- 字体和图片均在本地，不请求第三方字体、广告或分析脚本；支持键盘焦点、跳过导航、手机菜单与减少动画偏好。

## 部署(Cloudflare Workers)

官网跑在 **Cloudflare Workers** 上:用官方 OpenNext 适配器
([@opennextjs/cloudflare](https://opennext.js.org/cloudflare))把 Next.js 打成一个 Worker,
静态资源通过 Workers 的 assets 绑定返回。

### 自动发布（GitHub main）

私有仓库: https://github.com/moutsea/koitab 。Cloudflare Workers Builds 连接该仓库,
每次推送到 `main` 后自动安装依赖、运行扩展回归测试、生成更新日志和下载包,
然后构建、检查多语言 SEO 产物并部署官网。

Cloudflare 构建设置:

- 生产分支: `main`
- 根目录: `nextjs`
- 构建命令: `npm run build:worker`
- 部署命令: `npm run deploy:worker`
- Node.js: `22.22.0`（`nextjs/.node-version`）

发布时更新 `extension/manifest.json` 和 `CHANGELOG.md`,运行
`python3 tools/build-site.py` 后提交并推送。构建状态在
Cloudflare **Workers & Pages → koitab → Deployments** 查看。

### 手动部署

```bash
cd nextjs
npm ci
npx wrangler login      # 首次授权
npm run deploy         # 回归测试 + 生成下载包 + 构建 + 部署
```

### 绑定 koitab.com

`nextjs/wrangler.jsonc` 已写好自定义域路由,部署时自动把域名挂到 Worker:

```jsonc
"routes": [
  { "pattern": "koitab.com", "custom_domain": true },
  { "pattern": "www.koitab.com", "custom_domain": true }
]
```

域名在你同一个 Cloudflare 账号下,证书与 DNS 由 Cloudflare 自动处理,通常几分钟生效。
若部署时报域名相关错误(比如域名不在当前账号),先把这两行删掉、部署成功后再到
**Workers & Pages → koitab → Settings → Domains & Routes** 手动 Add custom domain。

### 注意事项

- Worker 名字固定为 `koitab`(见 `wrangler.jsonc` 的 `name`);改名字等于换一个 Worker
- 每次部署都是新版本,静态资源按部署版本隔离;看着像旧版就硬刷新或无痕窗口验证
- 扩展更新后:`manifest.json` 升版本 → `build-site.py`(重打 zip 与 releases.json)→ 部署
- 发布包刻意**不含** `debug.html`(开发自查工具);用户反馈异常时让其用仓库完整版跑诊断页
- 旧的 Cloudflare **Pages** 项目(基于已废弃的 `dist/`)可以删掉了 —— 现在走 Workers
- 上架 Chrome Web Store 后把首页下载按钮换成商店链接即可(改 `nextjs/components/site-page.tsx` 与五语文案),zip 仍可作备用分发

## 使用说明

点工具栏图标打开弹窗,顶部三个 tab:

- **🩺 诊断** — 点「开始诊断」自动统计:重复多少、跨窗口多少、几天没用的多少,
  每行一根朱砂/墨色比例条;报告下方给**整理与归档的结果预览**
  (会生成几个分组、关几个重复、收几个散标签、归几条书签),看完再决定动不动手。
  归档没候选时会**如实说明原因**(读不到时间 / 最旧的也才 X 前用过 / 都是在看),
  而不是干巴巴一句"没有";整理范围与折叠阈值都是整理卡里的一行小设置
- **🗂 标签页** — 搜索 + 按站点分组的标签列表,点分组标题折叠/展开
- **⭐ 收藏夹** — 两个分区:**KoiTab 收藏**(归档存 `chrome.storage.local`,可打开、可删、可清空)
  与 **浏览器书签**(**只读**展示整棵书签树 —— 搜索天然搜得到书签内容,但 KoiTab 绝不改动它们);
  点分区/夹子标题折叠展开、状态记住;「清空」只对 KoiTab 收藏分区开放

| 操作 | 说明 |
| --- | --- |
| 整理范围 | 「操作」页里「本窗口 / 所有窗口」切换,选择会记忆到下次打开 |
| 自动折叠阈值 | 「操作」页可配:一组达到 5 / 8 / 12 个自动收起,或「从不」(默认 8) |
| 停留的 tab | 关掉弹窗再打开,回到上次停留的 tab |
| 一键整理 | 依次执行 **关闭重复 → 分组收进当前窗口、散标签收进新窗口 → 收拾剩余标签**,结果汇总成一句提示 |
| 归档未用标签 | 超过 3 / 7 / 30 天(可选,默认 7 天)没用过的标签页,**先收进 KoiTab 自己的收藏夹(本地存储)再关闭**;正在浏览与固定的永不归档 |
| 点击分组标题 | **折叠 / 展开**该站点分组;折叠后只留「站点名 + 数量」 |
| 底栏「全部折叠 / 全部展开」 | 一次收起或展开所有站点分组,快速扫视都有哪些类别 |
| 点击条目 | 跳转到对应标签页(跨窗口时会先激活对应窗口) |
| 条目右侧 × | 关闭单个标签页;分组标题右侧 × 关闭该站点全部标签页(悬停出现) |

### 标签页太多时:按站点折叠

同站点的标签页会被收进一个分组,点标题栏即可折叠。分组标题是**吸顶**的,
滚动长分组时始终能看到当前属于哪个站点。

- **折叠后只留域名**:收起后整组隐藏,只剩标题栏上的「站点名 + 数量」,
  一眼扫过去就是一排干净的站点。全部折叠时不再夹着某一条标签页的信息
- **不用展开也能扫视**:标题栏左侧的色点与分组颜色一致,
  右侧数量告诉你这一组有多少个标签页
- **自动折叠大分组**:没有手动操作过、且标签数达到阈值的站点,打开弹窗时默认收起,
  首屏更短更好扫视。阈值在「操作」页可配(5 / 8 / 12 / 从不,默认 8)。
  只要手动展开过一次,就再也不会被自动折叠覆盖
- **偏好模型**:折叠状态记录为「明确偏好」(`collapsed` / `expanded`),存在
  `chrome.storage.local`;用户操作永远优先于自动折叠。保存时会自动清理已不存在的站点,
  并兼容 1.0.0 的旧字段
- **搜索时会强制展开**:否则命中的标签页会被折叠藏起来。此时标题不可点击,
  底栏的「全部折叠」按钮也会置灰并在提示里说明原因;清空搜索后恢复原有折叠状态
- 底栏按钮文案随状态切换:还有展开的分组时显示「全部折叠」,全部收起后显示「全部展开」

### 归档未用标签(先收藏、再关闭)

顶部阈值选一个(3 / 7 / 30 天没用过,默认 7 天,会记住),点「归档未用标签」:

1. 每个标签页先写进 **KoiTab 自己的收藏夹**(`chrome.storage.local`,按站点分组、最近归档在前)
2. 确认存盘成功,再重新核验每个标签的 URL、窗口、访问时间、激活与固定状态,只有未变化且仍符合归档条件才关闭 —— 这是"收藏式关闭"的底线
3. 想找回:「收藏夹」页的 KoiTab 收藏分区,点击即在当前窗口打开

**为什么不写浏览器书签**:书签树是各家浏览器/策略版本差异的重灾区
(实测踩过「search 不返回文件夹」「其他书签容器 id '2' 不存在」两个坑)。
收藏是 KoiTab 的功能,数据就该 KoiTab 自己管 —— 与浏览器书签**完全解耦**。
浏览器书签仍然出现在收藏夹页里,但**只读、用于搜索**,KoiTab 不写它们一个字节。

安全边界,宁可漏、不可误杀:

- **正在浏览的标签页和固定标签页永不归档** —— 也因此任何窗口都不可能被归档到关闭
- 拿不到 `lastAccessed`(Chrome 121 以下)的标签页一律跳过
- 浏览器内部页(chrome:// 等)与空 URL(导航中)不收
- 同一 URL 开多份时,收藏只记一份、标签全关闭;隔几天再开到同一页,再归档算更新不算重复存
- 读取或存盘失败 → 一个标签都不关,旧收藏保持原样
- 存盘期间导航、激活、固定、移动或访问时间变化的标签页保留不关
- 归档遵循顶部的「整理范围」:「本窗口」范围只归档当前窗口

> `lastAccessed` 在浏览器重启后是否保留,尚未确证(可用扩展自带的 `debug.html`
> 诊断页验证)。但因为产物是可找回的收藏条目而不是删除,误判的代价只是"多收了一个其实用过的页",
> 从「收藏夹」页能找回来 —— 这正是"先收藏再关闭"的意义。

### 一键整理做了什么

顺序是固定的,而且这个顺序很关键:

1. **关闭重复网页** — 以「保留 hash、路径及查询参数的完整 URL」判断重复;保留优先级:固定 > 正在浏览 > 更早打开。
   先做这一步,后面几步要处理的标签更少,也不会把即将关闭的标签搬来搬去
2. **取消孤儿分组** — 只剩 1 个标签的分组已经没有意义,自动取消。
   排在集中**之前**:取消分组后这些标签就变回「未分组」,也就能参与集中
   (比如分组里孤零零 1 个 GitHub 标签,取消后就能和别的窗口的 GitHub 凑成一组)
3. **分组收进当前窗口,散标签收进新窗口**(仅「所有窗口」范围执行) — 见下节。
   必须在成组之前搬运:Chrome 的分组无法跨窗口,先分组就白做了
4. **收拾剩余标签** — 把还没成组的同类标签就地成组(主要作用在固定标签聚集处和「本窗口」范围)
5. **重排** — 把未分组的标签页挪到分组右边,让分组彼此挨着。排在最后:
   前面几步会改变标签的分组归属,重排要按最终归属来摆放

每步之间都会重新查询标签列表,避免基于已关闭 / 已移动的过期数据做规划。
按钮悬停会提示本次将执行哪几步(例如「关闭 3 个重复 → 把 5 个站点集中到当前窗口 → 把 4 个散标签收进新窗口」);
如果什么都没得整理,按钮会置灰。

### 整理成两个窗口

在「所有窗口」范围下点「一键整理」,结果是一目了然的两个窗口:

- **当前窗口 = 分组的展示窗口** — 所有窗口里同一站点的标签都收进这里,按站点成组
- **新窗口 = 散标签的收纳窗口** — 站点合计只有 1 个标签、构不成分组的标签收进这里。
  **排列不打乱你看到的样子**:当前窗口的散标签整块在前、其余窗口按窗口编号整块跟随
  (窗口之间不交错),同一窗口内保持标签栏从左到右的顺序 ——
  你拖拽调整过的顺序也会被原样保留(按位置排,不按打开时间排)
- **其他窗口被搬空后关闭** — 只有固定标签的窗口会留下来(固定标签不搬动)

- **归并标准是跨窗口的**:某站点在所有窗口合计 ≥2 个标签就会被集中。
  所以"窗口 A 一个、窗口 B 一个"的同站点标签也会被合并到一起
- **分散在多个窗口就一定合并**:哪怕每个窗口里的分组各自都已经很整齐,
  只要它们在不同的窗口里,就会被集中过来 —— 否则分组会分处两个窗口
- **为什么让当前窗口当分组窗口**:弹窗依附于当前窗口,窗口一被关掉弹窗就消失、
  整理会中断在半路(标签已经搬走、却还没成组,留下一个烂摊子)。
  让当前窗口当分组窗口,它在这种情况下**只收不搬**,永远不会被搬空,这个风险就不存在
- **散标签不会越收越多**:散标签已经全在同一个窗口里(且不是当前窗口)时就不再搬动,
  所以重复点「整理」不会有任何多余动作,窗口也不会越点越多
- **固定标签留在原窗口,也不参与分组**:Chrome 不允许固定标签进入分组,
  它们保持原样(通常是邮箱 / 日历这类常驻页)
- **被搬空的窗口会关闭**:原窗口的标签全被搬走时,Chrome 会关掉这个空窗口。
  标签不会丢,它们都在上面说的两个窗口里;提示里会说明关闭了几个窗口
- **不抢焦点**:新建窗口时以 `focused: false` 创建,不会被拽走,弹窗也不会因失焦被关闭
  (否则你就看不到整理结果了)

#### 什么时候什么都不做

如果**当前窗口里没有任何站点能构成分组、也没有固定标签**,那就没有"让它留下来的理由":
把散标签搬走只会让当前窗口被关掉、弹窗中断。于是这种窗口会保持原样,按钮也会置灰。

「本窗口」范围下不新建窗口、不做任何跨窗口搬运,仍是在当前窗口内原地成组。

### 重排:分组靠左,未分组靠右

整理后,同一个窗口里属于分组的标签页会彼此挨着排在左边,未分组的标签页统一排到右边,
不再交错。**你的分组不会被我们打乱**:

- **只移动「未分组且未固定」的标签页**,并且一律追加到窗口末尾。
  分组内的标签页一个都不动,所以「同组内成员的顺序」「分组与分组之间的先后顺序」完整保留
- **为什么不直接把分组挪到左边**:Chrome 要求同一分组的标签页在标签栏里必须连续。
  去移动分组内的标签页,中途就可能把分组拆开,甚至让标签落进别的分组区间而被"吸"进那个分组。
  只把未分组标签追加到末尾,则永远不会落到任何分组区间内部
- **固定标签页不参与重排**:Chrome 要求固定标签只能在最左侧,它们本来就排在分组左边
- 已经排好的窗口不会产生任何多余操作(一次 `chrome.tabs.move` 都不会调用)

### 站点是怎么归类的

按**可注册域名**归并:同一站点的不同子域算作一个站点,
`zhuanlan.zhihu.com`、`www.zhihu.com`、`zhihu.com` 都会归入 `zhihu.com` 同一个分组。

扩展拿不到公共后缀列表(PSL),所以用「最后两段 + 常见多段后缀兜底表」来判断:

- `m.weibo.cn` → `weibo.cn`、`blog.csdn.net` → `csdn.net`、`pan.baidu.com` → `baidu.com`
- 不误判:`a.com.cn` 与 `b.com.cn` 保持各自独立;`foo.co.uk` / `bar.co.uk` 同理
- 私有后缀也保持独立:`user1.github.io` ≠ `user2.github.io`、`x.blogspot.com` 各自一组
- 副作用:同一主域下的不同子域会合并,例如 `docs.google.com` 与 `mail.google.com`
  都会归入 `google.com`

### 「所有窗口」是怎么合并的

Chrome 的标签分组**不能跨窗口**——一个分组只能存在于一个窗口内,`chrome.tabs.group()`
要求传入的标签 id 全部属于同一窗口,否则会直接报错。

这正是整理要分两步走的原因:**先把同站点的标签都搬进同一个窗口,再成组**。
集中到当前窗口之后,每个站点一个分组,组内标签连续排列。

- **同一站点使用同一个分组颜色**(按域名哈希取色),一眼就能对应
- 弹窗里每个条目右侧带窗口徽标:「本」= 本窗口,数字 = 其他窗口

### 整理成两个窗口(仅在「所有窗口」下执行)

若你希望把散落在多个窗口的同类标签页集中起来,切到「所有窗口」再点一键整理即可。规则:

1. 只处理**所有窗口合计 ≥2 个标签**的站点;只有 1 个标签的站点不会成组
2. 分组一律收进**当前窗口**,散标签收进**新建的窗口**
   (分组无法跨窗口,所以先集中、再成组)
3. **固定(Pinned)标签不搬动**,留在原窗口,也不参与分组
4. **当前窗口不会被搬空**,其他窗口允许被搬空并关闭;去重时也有"别把窗口搬空"的保护
5. 同一站点最终只会留下一个分组:该站点已有的分组会被重新收拢到一起

被跳过的部分会在提示里说明,例如
`已关闭 2 个重复标签页 · 5 个标签页归入 2 个站点分组(1 个重复为避免窗口被清空而保留)`。

## 技术说明

- 基于 **Manifest V3**,仅需 `tabs` + `tabGroups` + `bookmarks` + `storage` 四个权限
- 最低 Chrome / Edge 121+,统一满足存储 Promise 与 `lastAccessed` 的 API 要求
- 无构建步骤、无第三方依赖,纯 HTML/CSS/JS
- **图标样式**:宣纸色圆角底板(`#f5f0e4`,与界面同调)+ 手绘黑墨笔触;浅色/深色工具栏都有稳定对比度,无需按主题切换
- **调整主体大小**:改 `tools/apply-logo.py` 里的 `FILL`(墨迹占图标比例)后重跑;
  `python3 tools/apply-logo.py --preview` 会生成 `preview/fill-comparison.png`,
  横向四档放大比例、上下两行分别为浅色/深色工具栏背景,便于直观挑选

### logo 处理流程

1. 按 `C = a*F + (1-a)*255` 反混合,把白纸背景转为透明并还原墨色(保留红色笔尖)
2. **按阈值清除纸张噪点后再裁剪**到墨迹包围盒 —— 否则 JPEG 噪点会让包围盒等于整张画布,
   主体就会显得很小
3. 按 `FILL` 缩放到宣纸色圆角底板上(`PAPER_PLATE` 常量),小尺寸额外做锐化,最后加一道极细描边

替换 `assets/logo-source.jpg` 后运行 `python3 tools/apply-logo.py`(需 Pillow)即可重新生成全部图标,同步写入 `extension/icons/`、`nextjs/public/assets/` 和 `landing/assets/`。

底板颜色由 `apply-logo.py` 里的 `PAPER_PLATE` 决定 —— 手绘的墨迹与红笔尖原样保留,只把白色底板换成了宣纸色。
